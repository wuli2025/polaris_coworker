# 循环协议（loop/PROTOCOL.md）v1.0

> 执行者（长期为 Opus 4.8，通过 Claude Code 定时会话运行）每轮照本手册走完 7 步。
> 一轮 = 服务**一个**人格 + 一次预算内的完整闭环。宁可一轮只落一条好规则，不可一轮灌十条水规则。
> 修改权限：流程参数（预算/阈值）可由执行者提案、人类确认；步骤结构仅人类可改。

## 第 0 步 · 接棒（≤5 分钟）

1. 读 `design-dna/README.md`（三条铁律）→ 读本文件 → 读 `loop/journal/` 最新一篇。
2. 从日志「下一棒」栏取本轮人格与采集侧重；若无日志或无指示，按人格轮换表取下一个
   （轮换表 = personas/ 下按文件名字母序循环，跳过 status: featured 的成熟人格，它们两轮才轮一次）。
3. 在心里回答：上一轮留下什么未完成？本轮**一个**最想验证的问题是什么？写进本轮日志开头。

## 第 1 步 · 采集（Collect）

- 从 `loop/sources.md` 按轮换规则选 **3–5 个源**（至少 1 个中文源、至少 1 个上轮没用过的源）。
- 用 WebSearch / WebFetch 抓取；每源浏览 5–10 个候选案例，用 `foundation/rubric.md` 快评。
- **只收 ≥28 分的案例**，目标本轮 4–8 个；连续 15 个候选不达标 → 换源。
- 采集面向本轮人格，但撞见其他人格的示范级案例（≥32 分）顺手也收（标注归属）。
- 预算：联网动作 ≤40 次。抓不到图就抓文字与代码：落地页可直接 fetch HTML 读它的 CSS 变量、字号、间距——**代码是最诚实的设计文档**。

## 第 2 步 · 解构（Deconstruct）

每个入选案例写一张证据卡到 `evidence/YYYY-MM/<序号>-<slug>.md`，格式见 `evidence/README.md`。
解构必须量化：hex 色板 + 角色、字号阶梯与比率反推、间距档位、网格轴、装饰词表、动效清单、rubric 七维分 + 每维一句证据句。
最后一栏必答：**「它印证或挑战了哪条公理 / 哪条人格现行规则？」**——这栏是第 3 步的原料。

## 第 3 步 · 提炼（Distill）

对照本轮人格的现行文件，从证据卡里提出 **1–3 条 delta**（多了砍掉，留最强的）。每条 delta 写成：

```
Δ 标题：一句话（改哪节、加/改/删什么）
类型：add-rule | refine-rule | drop-rule | new-recipe(色板/字阶/版式) | fix-error
锚定：[A?] + [ev:YYYY-MM/xxx] × ≥2      ← 双重锚定，缺一即废
陈述：写进人格文件的最终措辞（直接可粘贴）
赌注：这条规则赌的是什么？若错，样张会出现什么症状？
```

- drop-rule 同样光荣：发现人格里某条规则被反复证伪或从未被引用，删除它就是本轮成果。
- 若证据聚类明显不属于任何现有人格（连续两轮出现同类高分案例且无家可归）→ 不写 delta，改写**新人格提案**进日志（含暂名、宣言草稿、已有证据卡列表）。新人格需人类点头才建档，建档后 status: incubating，集满 8 张证据卡 + 一次 ≥28 分样张才可标 stable。

## 第 4 步 · 对抗评审（Verify）

换一副冷酷面孔（或另开子代理），逐条 delta 过四问：

1. **地基冲突**：与 foundation 任一公理、任一票否决项冲突吗？冲突 → 废。
2. **时尚半衰期**：这是 10 年级别的规律，还是 18 个月的潮流？潮流可以进「装饰语汇」，**不可以**进「人格宣言/美学权重」。拿不准 → 降级为 provisional。
3. **人格纯度**：这条规则让人格更像它自己，还是更像别人？（例：给 wabi-sabi 加渐变=人格污染，废。）
4. **可执行性**：生成模型照这条措辞能直接落手吗？含糊词（“适当”“尽量”）→ 打回重写成可检查的量化表述。

评级：S（直接落盘）/ A（落盘）/ P（provisional，落盘但下轮复验）/ 废。全废也是合法结果，如实记日志。

## 第 5 步 · 落盘（Consolidate）

- 把 S/A/P delta 写进人格文件对应章节，规则尾部标锚定 `[A?][ev:…]`；版本号按语义化递增；版本志加一行。
- 检查行数预算：**≤400 行**。超了 → 删除最弱规则（最久未被证据引用者优先），删除也记版本志。
- frontmatter 更新 `updated` / `evidence_count`。
- git 提交（仅 design-dna/ 目录）：`dna(<persona-id>): <一句话> [loop#N]`。

## 第 6 步 · 实战校验（Field Test）

- 用升级后的人格生成**一份样张**：奇数轮做 deck.html（8–10 页），偶数轮做 site.html——按人格第 10 节「实现映射」走全流程（读 deck-studio/web-studio 的 SKILL.md 与 design.md，成品自包含单文件）。
- 样张内容用固定基准脚本（journal/BENCHMARK.md 里的固定文案，保证轮与轮可比）。
- 存到 `evidence/samples/<persona-id>/vX.Y.Z-{deck|site}.html`。
- 按 rubric 七维打分（每维写证据句），与该人格上一版样张比较：
  达标 → 通过；跌 ≥3 分 → **回滚本轮全部 delta**（git revert），日志写清哪条赌注输了。

## 第 7 步 · 交棒（Journal）

写 `loop/journal/YYYY-MM-DD-loop<N>.md`：

```
# Loop N · <persona-id> · YYYY-MM-DD
本轮问题：…
采集：源 ×k，候选 ×m，入选 ×n（证据卡链接）
Delta：Δ1(S 落盘) Δ2(P) Δ3(废，原因)
样张：路径 + 七维分 + 对比上版 ±
教训：一句话（下轮的我该避开什么）
提案（如有）：改地基 / 新人格 / 调参数 —— 等人类批
下一棒：人格 <id>，侧重 <方向>，优先复验 <provisional 规则>
```

## 全局纪律

- **预算**：一轮联网 ≤40 次、新增证据卡 ≤10 张、delta ≤3 条、总时长目标 ≤1.5h。到预算即收尾，未完成的进「下一棒」。
- **节律**：建议每周 2–3 轮（cron）；全部 8 人格轮完一圈 ≈ 3–4 周，一圈结束后跑一轮「圈审」：只做跨人格体检（重复规则合并、人格间边界重划、给人类的季度提案汇总），不采集。
- **版权**：证据卡只记录解构出的规律与参数，不复制原作品的文案/代码/图片；样张内容一律用基准脚本。
- **诚实**：打分向低不向高；回滚不丢人，灌水才丢人。人格文件的公信力 = 这个系统的全部资产。
