# P7 端到端演练计划（真实运行，不是单元测试）

目标：证明重构后的 Polaris 在真实进程、真实网络、真实模型下"耐用好用"。每项演练记录命令、环境、实际输出与结论到 `docs/drills/`，失败项转为修复任务。

## D1 Agent 主链路（真实模型）
- 构建 agentd 生产包（`scripts/pack-agentd.mjs`）与服务端壳；以 Pi 后端启动，用**真实模型**完成：普通对话、带工具调用的编码任务（读/写/执行，auto-current 档位）、图片附件、长对话触发自动压缩、中途 abort、steer/followUp、切换提供商（空闲会话重开保留历史）。
- 指标：首字延迟、单轮耗时、取消到 done 的时间、内存占用；与旧 claude CLI 后端对比（如可用）。
- 需要：一个可用的模型凭据（见"待用户决定"）。

## D2 故障与恢复
- 运行中 `kill -9` agentd：前端收到 error→done，supervisor 指数退避重启，会话按 id 恢复历史。
- 连续崩溃触发熔断，状态接口与诊断如实显示。
- 凭据锁：持锁进程被强杀后另一进程回收（真实双进程）。
- 断网/模型 401/429：错误分类与提供商故障切换。

## D3 权限与沙箱（真实 Docker）
- 四档权限逐档实操；manual 档弹窗允许/拒绝/超时；符号链接 + `..` 越权写入被拒（P3 复现用例在真实会话中复跑）。
- 真实沙箱容器：只挂项目与只读知识库，容器内看不到 `~/Polaris/data`、`*.key`；`docker inspect` 核对挂载与 `cap-drop`/`no-new-privileges`；沙箱 bash 失败命令返回非零退出码；沙箱不可用时报错不回落宿主。
- 补 P3b 遗留：真实容器内挂载可见性、项目本身是指向受保护目录的符号链接。

## D4 互联（本机多容器模拟多设备）
- 用 `deploy/singapore/` 的 Compose 在本机起：权威 + iroh-relay（按 Dockerfile.relay 本地构建）+ 两个成员主机（polaris-server）+ 一个"新设备"。自签证书或测试 CA。
- 演练：账号密码登录即成网；relay 下发并生效；新设备立即全权、旧设备收到通知并一键吊销，吊销后新设备在一个拉取周期内失去访问；新设备窗口期内高风险操作需旧设备批准，自批被拒；离线时高风险被拒、已有会话可用；篡改/回滚吊销清单被拒；账号枚举修复（R11）对外响应一致；频控 429。
- 备份→恢复→指纹校验全流程（真实 age）。

## D5 打包与跨平台
- Linux：Tauri 构建（deb/AppImage），安装后首次启动 doctor 报告 Pi 运行时就绪（随包 Node + agentd）。
- Windows/macOS：本机（WSL）无法构建，列为**需要用户在 Windows 上执行**的步骤清单（随包 MinGit bash、System32 WSL bash 排除、Job Object 子进程随父退出、长路径）。
