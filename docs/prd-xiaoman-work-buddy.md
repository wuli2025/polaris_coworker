## 0. 结论先行

1. **它得先是个"东西"，才谈得上是个助手。** 一个只在对话框里出现的 AI，用户永远只把它当工具。**让用户亲手拍一张照片、把它捏成一个形象放在屏幕角上**，这件事的留存价值可能比任何一个功能都大——因为那一刻它从"某个 AI"变成了"我的小满"。这也是本版最大的新增：**形象工坊**（§5.2）。

2. **它得管你的身体。** 工作搭子跟工作助手的差别，全在这里。助手管活，搭子管人：**水喝了没、坐多久了、饭点过了没、几点了还不睡**。这几件事技术含量为零，做好的难度全在**分寸**——什么时候开口、开口几次、被无视了怎么办（§5.3）。做不好就是又一个被关掉的提醒软件。

3. **录音是这个产品最值钱的一条腿。** 你每天最有信息量的时刻不在电脑前，在跟人说话的那半小时——需求评审、跟老板对齐、跟客户扯皮。**这半小时的产出目前是零**：你记了几行字，剩下的第二天就忘了。小满把它录下来、转写、分说话人，**五分钟内还你四样东西：纪要、待办、给你的三条提醒、以及——如果这场聊的是个新东西，一版可以直接改的初稿**（§5.6）。这一条别人不是做不了，是没人把"录音笔 + 你的工作上下文 + 能干活的 Agent"接在一起过。

4. **范围必须由你来划。** 一个能读你文件、能跑命令、能上网、还能替你说话的东西，如果边界模糊，没人敢真用。所以有一张**共事约定卡**：能碰哪些文件夹、能不能改、能不能跑命令、能不能花钱、几点之后别烦我。三档预设，逐项可调，越界必问（§5.7）。**信任不是靠承诺建立的，是靠一张能看见的清单。**

5. **技术上仍然不需要新引擎。** Polaris 已经有：人格层（`persona.rs` + `CLAUDE.md` 分层注入）、记忆层（`echo.rs` 每日做梦 + `memory/` 车道）、技能层（`skills/`）、日程层（`automation.ts`）、形象层（`DigitalWorker.vue`）、**生图**（`imagegen.rs` + `provider/image_store.rs` + 火山 seedream）、**语音**（`voice/` + 火山 ASR）、**手机录音**（安卓壳 `mobile/src/lib/recorder.ts` 已经在了）、工具层（Claude Code 全家桶）。**这份 PRD 八成的工作是把这些接成一条闭环。** 新增预算：Rust ≤2000 行，前端 ≤1600 行，**零新增进程、零新增数据库、零新增第三方依赖**。

6. **数据全在你自己的盘上。** 照片、录音、转写、饭、作息——这些比代码敏感得多。全部明文落在 `~/Polaris/` 下面，**不上传、不训练、可导出、可一键删干净**。云端模型只在你自己配置了 key 的时候才被调用，且每一类数据出不出门由你逐项开关。这既是产品原则，也是唯一能让人放心开麦的前提。

## 1. 它是什么

### 1.1 为什么不叫「子房」了

张良是好典故，但它错在三个地方：要查、太远、太谋士。**「军师」和「搭子」是两个物种**——军师站在你身后，搭子坐在你旁边。

**「小满」**，二十四节气第八个，物致于此小得盈满：**麦子将熟未熟，籽粒开始饱满但还没满**。

选它的三个理由：

- **它是一个状态，不是一个人格。** 名字里不带承诺（没有"永远""陪伴""你的谁"），但带了这个产品真正的态度：**今天比昨天满一点就够了，不追求圆满。**
- **它天然对着产品口径。** 每天推进一点点、把水杯满上、这周的账满不满——名字和功能长在一起。
- **它无性别、无亲密关系暗示、不需要解释。** 中文使用者听一遍就记住了，且不会被理解成虚拟伴侣。

代号 `xiaoman`，目录 `~/Polaris/xiaoman/`。**用户可以随时改名**——设置里一行输入框，改完全局生效（形象是他自己上传的，名字当然也该是他自己起的）。

### 1.2 默认形态

一只巴掌大的**陶土色小团子**，趴在屏幕右下角。圆的，没有五官细节，只有两个点和一条线。

**为什么故意做得这么简单**：因为你打开软件五分钟之内就会把它换掉。默认形象存在的意义只是"在你上传自己的东西之前，这儿得先有个人"。

我们**不做** 3D 数字人、不做直播级建模、不做虚拟主播。理由很实在：成本高、拖性能、且**精细度跟信任度根本不相关**。一个像素小人和一个 8K 数字人，对"它记不记得我昨天说的话"这件事没有任何影响。

### 1.3 它跟"AI 助手"的差别（一句话版）

| | AI 助手 | 小满 |
|---|---|---|
| 在哪 | 对话框里，你打开它才存在 | 屏幕角上，一直在 |
| 长什么样 | 一个头像 | **你拍的那张照片变成的东西** |
| 管什么 | 你问的事 | 你的活 **+ 你的身体 + 你的日程 + 你的会** |
| 怎么变懂你 | 你告诉它 | 你纠正它、它自己看你的痕迹 |
| 归谁 | 平台账号 | 你的硬盘 |
| 能干到哪 | 你每次授权 | **一张你自己划的范围卡** |

## 2. 市场：为什么是现在

### 2.1 一条监管线把赛道劈成两半

《人工智能拟人化互动服务管理暂行办法》（网信办等五部门，2026-04-10 公布，2026-07-15 施行）第二条：**"提供智能客服、知识问答、工作助手、学习教育、科学研究等服务，不涉及持续性的情感互动的，不适用本办法。"**

这条给我们划了一条清楚的路：**小满是工作搭子，不是情感陪伴产品。** 它管你喝水、管你的会、帮你干活；它不是恋人、不是树洞、不提供"陪我聊会儿"。这不只是合规姿势，也是产品选择——把这条守住，产品反而更聚焦（详见 §9）。

### 2.2 三个正在发生的窗口

**① 几百万人的人设正在被清空。** 豆包、千问、元宝 2026-07 前后集体下架自建智能体，**10 月清空全部用户人设与对话数据**。养了一两年的东西一句话没了，用户在微博发公开信抗议。我们的答案很短：**你的小满长在你自己的硬盘上，没有任何平台能下架它。**

**② 钱在生产力这边。** 公开数据：情感陪伴产品人均支出约 **5 美元**，生产力工具人均约 **56 美元**——11 倍。星野付费用户 139 万但 ARPU 仅 5 美元，日下载从 2 万+ 跌到 7 千以下，高频吐槽是"AI 生成的回答很言之无物"。腾讯 WorkBuddy 企业版敢收 **¥198/人/月**，因为它交付的是活儿。

**③ AI 录音笔卖疯了，但只做到一半。** Plaud、讯飞、有道这一批硬件把"录音→转写→摘要"跑通了，卖得很好，说明**需求是真的**。但它们止步于"给你一份纪要"——因为它们不知道你在做什么项目、不认识你说的那些人名和代号、更不能替你把待办排进日程、把初稿写出来。**纪要不是终点，是原料。** 小满手里有你的项目、记忆、技能和一整套工具，这是录音笔缺的那一半。

### 2.3 我们的坐标

```
                  管你的活 + 管你的人
                          ▲
       AI 录音笔          │      ★ 小满
       （只到纪要）        │   （形象 + 身体 + 会 + 活，全在本地）
   ───────────────────────┼───────────────────────►  懂你 / 是你的
       通用 ChatBot       │      陪伴类 App
       （谁用都一样）      │   （懂你但不干活，且已被监管收口）
                          ▼
                   只回答你问的
```

右上角是空的。要同时做到"真干活"和"真是你的"，得同时有：能跑任意工具的 Agent 底座（Polaris 有 Claude Code）、长期私有的记忆载体（本地 KB + memory 车道）、能被用户捏形状的形象与人格（本 PRD）。**这三样凑齐的产品，现在市面上没有。**

## 3. 用户与场景

### 3.1 目标用户

| P | 画像 | 为什么是他 | 最先打动他的 |
|---|---|---|---|
| **P0** | **独立开发者 / 技术负责人**（Polaris 现有用户） | 已经在用，工作痕迹结构化 | 早上的雷、失败托底、这周的账 |
| **P0** | **会多的人**（产品经理、项目经理、创业者、销售） | 每天 2–5 场会，**信息全在嘴里，产出为零** | **录音搭子**——这拨人第一次用就会震一下 |
| **P1** | **久坐工作者**（设计、运营、写东西的） | 身体最先扛不住，且工作痕迹散 | 身体节律 + 形象工坊 |
| **P1** | **小团队 leader**（3–15 人） | 协作模块已有主机/成员/项目体系 | 会后待办自动分派、周报聚合 |
| **P2** | 从豆包/星野迁移的人设用户 | 存量大、动机强 | 形象迁移 + "带得走"证明 |

### 5.2 F2 · 形象工坊：把一张照片捏成它 ★

**这是本版最重要的新增功能，也是留存的锚。**

#### 5.2.1 输入：什么都行

一张照片。你的猫、桌上的手办、一只袜子、随手画的涂鸦、游戏截图、你家狗。**唯一的限制在 §5.2.5。**

入口三个：形象工坊页拖文件 · 手机端直接拍 · 对话里把图片扔给它并说"用这个当你的样子"。

#### 5.2.2 处理：三步，四十秒

```
① 看懂            多模态理解一遍：这是什么、什么颜色、什么姿态、有什么特征
                  （"一只灰色塑料鲨鱼，圆眼睛，白肚皮，嘴微张"）
                    ↓
② 定形            按你选的风格生成一张【角色定义卡】——九宫格，同一个角色的
                  正面/侧面/背面 + 三个表情 + 三个姿态。
                  这张卡是后面所有帧的**唯一参考图**，一致性全靠它。
                  风格六选一：陶土 · 毛毡 · 像素 · 水墨 · 贴纸 · 软胶
                    ↓
③ 出帧            以角色定义卡为参考，生成九张状态帧（下表），
                  统一透明底、512×512、PNG
```

**九张状态帧**（对应 §5.2.4 的状态机）：

| 帧 | 什么时候出现 |
|---|---|
| 待着 | 没事干，默认姿态 |
| 干活 | 对话中 / 自动化跑着 |
| 想事 | 检索 / 深度搜索中 |
| 递东西 | 有东西给你（简报、纪要、初稿） |
| 喝水 | 喝水提醒 |
| 伸懒腰 | 起身提醒（点"一起"时它也动） |
| 打盹 | 23:00 之后 + 没事 |
| 挠头 | 出错 / 失败托底 |
| 庆祝 | 发版成功 / 这周的账 |

#### 5.2.3 工程实现

| 环节 | 复用什么 | 备注 |
|---|---|---|
| 看懂输入图 | 多模态图片理解（方舟 doubao-seed 系 / 已有 provider 链路） | 输出一段结构化角色描述 |
| 生成 | `src-tauri/src/imagegen.rs` + 火山 seedream | **记忆里的坑：AgentPlan key 走 `/api/plan/v3/images/generations`，且只放行 `doubao-seedream-5.0-lite`** |
| 存 | `provider/image_store.rs` | 帧落 `~/Polaris/xiaoman/avatar/<setId>/*.png`，明文 |
| 显示 | `DigitalWorker.vue` 改造 | 从内嵌 SVG 改为「帧图优先，SVG 兜底」 |

**一致性怎么保住**（这是形象类功能唯一的真难点）：
1. 角色定义卡是**唯一真源**，九张帧全部以它为参考图 + 同一段角色描述文本 + 固定 seed
2. 每张帧生成后跑一次相似度自检（感知哈希 + 主色分布），偏差过大自动重试一次
3. 用户可以**单独重画任意一帧**，不用整套重来
4. 生成完给「全部九张一起看」的预览页——**不满意整套重来的成本是 40 秒，这比试图做到 100% 一致更实际**

**兜底**：没配生图 key / 生成失败 / 没额度 → 退回内置 6 款默认形象（陶土团子、猫、纸片人、像素小人、水墨小童、方块）。**形象工坊挂了不能影响任何其他功能。**

#### 5.2.4 状态机与常驻位

屏幕右下角常驻，96×96，可折叠成一个小点。**它不说话**——所有内容通过点开的「案头」抽屉给（F6）。

**绝不做的三件事**：
- ❌ 点它蹦出一句俏皮话（这是电子宠物，是豆包那 800 万里的一个）
- ❌ 无事弹窗（只有真有东西给你的时候才出红点）
- ❌ 播动画抢注意力（状态切换用淡入，不用弹跳）

#### 5.2.5 三条红线

1. **不给真人照片做写实数字人。** 上传真人照只做**卡通化/风格化 IP**，不生成写实人脸、不做换脸、不做"某个真人的分身"。**形象与人格解耦**——换了样子，它说话方式不变。
2. **不做名人 / 不做别人的脸。** 检测到疑似公众人物或第三方肖像时提示一次："这是别人的脸，做成你的搭子可能有点问题，换一个？"（提示，不硬拦——用户可能是拍的自己）
3. **不做形象商城。** 不卖皮肤、不出联名、不做角色广场。**它值钱是因为是你捏的，不是因为好看。**

**验收**
- [ ] 一张普通手机照片 → 九张帧全出，端到端 ≤90 秒（生图服务正常时）
- [ ] 九张帧的角色一致性人工盲评 ≥7/9 被判为"同一个角色"
- [ ] 生图完全不可用时，形象自动退回默认款，其余功能零影响
- [ ] 全部帧明文落盘可手动替换（用户塞自己画的 PNG 进去也能用）

### 5.3 F3 · 身体节律：管你喝水、起身、吃饭、睡觉 ★

**这个功能的技术含量是零，全部难度在分寸。** 市面上所有喝水提醒 App 都被卸载了，原因只有一个：**它们不看你在干什么。**

#### 5.3.1 三条设计原则（比功能本身重要）

**① 等空档，不打断。**
提醒不是到点就发，是到点后**进入等待队列**，等到一个自然空档才出现：
- 命令跑完 / 任务收尾的那一刻
- 无键盘输入 ≥90 秒
- 对话轮次结束且你没有立刻追问
- 最长等 20 分钟，还没空档就**这次算了**（不累积、不补发）

**② 被无视就退让，不加码。**
- 一次不响应 → 不追
- 连续两次不响应 → 间隔自动拉长（60 分钟 → 120 分钟）
- 连续三次 → 主动问一次："喝水这事我最近老提，要不要我先别管了？" **问完不管答不答，静默 7 天。**

**③ 不打卡、不统计、不排名、不成就。**
不做"连续喝水 7 天"、不做进度环、不做健康分。**一旦开始记分，它就从搭子变成了监工。**（周五的账里可以顺口提一句本周的水，见剧本八——**陈述，不评价，不追问**。）

#### 5.3.2 四件事的具体设计

| 事 | 默认节奏 | 怎么判 | 长什么样 |
|---|---|---|---|
| **喝水** | 60–90 分钟 | 上次响应时间 + 空档判定 | 一句话 + 喝水帧。点「喝了」即过 |
| **起身** | 连续在座 50 分钟 | 键鼠活跃度（**只读活跃/不活跃，不记内容**） | 一句话 + 3 分钟计时，可选「一起」 |
| **吃饭** | **学你的历史饭点**，不是固定 12:00 | 过去 14 天的进食记录（F13）+ 日程空档 | 过了你的常规饭点 40 分钟才提，一次 |
| **睡觉** | 23:30 起进入歇息 | 本地时间 + 当前是否有活跑着 | **不催睡**。23:30 后不再主动开口；凌晨 1 点后只在你说话时回应，并把明天第一步先备好 |

**关于睡觉这条要特别说明**：旧版剧本三是"劝你别熬夜"，那是错的——**没人喜欢被劝。** 新版的做法是**它自己安静下来**：晚上把所有主动行为关掉，把明天的第一步准备好，然后打盹。**你半夜还在干活的时候，最好的陪伴是不说话。**

#### 5.3.3 静音与开关

- 全局静音开关（一键，今天 / 本周 / 永久）
- 逐项开关（只要喝水不要起身，随便）
- **免打扰时段**（默认跟随日程：会议中全静音）
- `POLARIS_RHYTHM=0` 整条关掉

**验收**
- [ ] 连续敲键盘期间**零打断**（自动化脚本模拟 30 分钟连续输入，提醒次数 = 0，全部进队列等空档）
- [ ] 连续忽略三次后触发一次询问，之后 7 天静默
- [ ] 全天提醒总数 ≤6 次（喝水 ≤4 + 起身 ≤3 + 吃饭 ≤2，且总量封顶）
- [ ] 键鼠活跃度采集**只记时间戳与活跃布尔值**，不记按键内容（代码评审逐行确认）

### 5.4 F4 · 共事约定卡：你自己划它的范围 ★

一个能读你文件、跑命令、上网、还能替你说话的东西，**边界必须看得见**。

#### 5.4.1 三档预设

| 档 | 它能做什么 | 适合 |

| **只看不动** | 读指定文件夹、搜索、上网查、回答 | 刚上手 / 敏感项目 |

#### 5.4.3 越界怎么处理

它想做范围外的事时，**必须先说清楚要干什么、为什么**，一行：

```

                        [就这一次] [以后都行] [不行]
```

- 「不行」之后 **30 天内不再为同一件事请求**
- 所有授权记录落 `~/Polaris/xiaoman/grants.jsonl`，设置页可见可撤销
- **每一次自主执行都留痕**：做了什么、动了哪些文件、什么时候，进「今天替你做了什么」（F11）

#### 5.4.4 形象上体现

小满头上有个小小的**授权牌**，颜色对应当前档位（灰=只看 / 蓝=草稿 / 绿=自主）。这是唯一一处让形象承担信息功能的地方——**你一眼就知道它现在能干到哪。**

**验收**
- [ ] 三档预设切换后行为真的变（每档 10 条越界尝试，拦截率 100%）
- [ ] 「能替你发消息」默认关，且开启需要二次确认 + 一句明确说明
- [ ] 每次自主执行都能在「今天替你做了什么」里追溯到
- [ ] 花钱上限触发后停止并询问，不静默继续

### 5.5 F5 · 录音搭子：谈完一场，东西就在那了 ★★

**这是产品的第二个尖叫时刻，也是最值钱的一条腿。**

#### 5.5.1 录什么、怎么录

| 来源 | 怎么接 | 状态 |
|---|---|---|
| **电脑麦克风** | 系统默认输入设备 | P0 |
| **手机** | 安卓壳 `recorder.ts` **已经在了**，录完通过现有隧道回传桌面 | P0 |
| **蓝牙耳机 / USB 麦** | 作为系统音频输入设备，无需特殊适配 | P0 |
| **第三方 AI 录音笔** | 导入音频文件（拖进来 / 指定同步文件夹自动扫） | P1 |
| **线上会议** | 系统回环音频采集（Win WASAPI loopback） | P1 |

**开始录音有三种方式**：点小满上的录音按钮 · 说"帮我录一下" · 日程里标了"要录"的会议**到点提醒你是否开始**（**永远不自动开始**）。

#### 5.5.2 录音中：它在场，且所有人都知道

- 屏幕角上小满**举着录音牌**，红点常亮
- 系统托盘图标变红
- 手机端状态栏常驻通知
- 面板上一直显示已录时长 + 一个大的「停」

**一键告知**：开始录音时给一句可直接念/发出去的话——

> "我开个录音，回头整理纪要用，会后我把纪要发群里，你们谁不方便我就关掉。"

#### 5.5.3 录完：五分钟，四样东西

```
音频 → ① 转写（火山 ASR / 方舟 ASR，长音频分片）
       ↓
     ② 分说话人（谁是谁：先按声纹分 A/B/C，再用会议日程的参会人名单 + 
        对话里的称呼自动对号，认不出就留 A/B/C 让你点一下改）
       ↓
     ③ 对齐你的上下文（项目记忆 + 人名代号 + 上次同名会议的纪要）
       ↓
     ④ 四件套产出
```

**四件套**：

| # | 产出 | 硬要求 |
|---|---|---|
| **1** | **一页纪要** | 决定了什么 / 没决定什么 / 谁说的。**必须包含"没决定的"**——那才是会后最容易掉的东西 |
| **2** | **待办清单** | 每条带 owner + 到期 + 出处（"第 23 分钟老王说的"）。你自己的那几条**自动排进日程**，别人的只列不派（除非团队版 F20） |
| **3** | **给你的三条** | 这是纯 AI 录音笔做不了的：**你答应了但没写下来的 · 对方反复提但你转开的 · 悬着没人认领的**。每条必须能指回原话时间点 |
| **4** | **顺手的产物** | 判断这场会谈的是不是一个新东西（新功能/新方案/新项目）。是 → 直接写一版 PRD / 方案 / 报价单初稿落草稿箱，**绝不自动发出去** |

**产物落盘**：`~/Polaris/meetings/<date>-<title>/`，里面是 `audio.m4a`（默认 7 天后删）· `transcript.md` · `minutes.md` · `todos.json` · `draft-*.md`。全部明文。

#### 5.5.4 隐私：这是整个产品最敏感的地方

**六条硬规则**：

1. **绝不常开、绝不后台偷录。** 只有手动开始或明确确认过的日程触发才录。
2. **录音状态必须三处可见**（屏幕 + 托盘 + 手机通知），且**不可隐藏**。
3. **原始音频默认 7 天后自动删**（可改成"转写完立即删"或"永久保留"）。
4. **一键忘掉**：任何一场会都能整场删干净（音频 + 转写 + 纪要 + 产生的记忆条目），一次点击，不问第二遍。
5. **数据出不出门由你定**：转写走本地模型还是云端模型是一个明确的开关。选云端时，第一次会明确告诉你音频会发到你自己配置的哪家服务商。
6. **他人语音不入长期记忆**：只有**你自己的**待办、偏好、项目事实进 `memory/`。别人说的话留在这场会的文件夹里，不进人格、不进画像、不做声纹长期库。

**法律提示（产品内首次使用时展示一次）**：录你自己参与的对话在多数场景是合法的，但**告知在场者是基本礼貌，且在部分场景是法定要求**；录到的内容不要外传。这段话写在功能里，不藏在用户协议里。

#### 5.5.5 验收

- [ ] 45 分钟四人会议，端到端出四件套 ≤6 分钟
- [ ] 说话人分离准确率 ≥80%（四人以内、正常会议室），错的能一键改且改一次全局生效
- [ ] 「给你的三条」每条都能点回原话时间点，**编造率 0**（抽 20 条逐条对账）
- [ ] 「顺手的产物」在 10 场"聊新东西"的会里触发 ≥7 次，且初稿人工评「改比重写快」≥7/10
- [ ] 一键忘掉之后磁盘干净（音频/转写/纪要/记忆条目全清，`grep` 验证零残留）
- [ ] 录音期间三处状态可见，且无法通过任何设置隐藏

### 5.7 F7 · 纠正捕获：你改它一次，它记住

**这是"越来越懂你"的最短路径。**

**触发识别**（`prompt.rs` 新增纯函数 `detect_correction`）：

| 类型 | 信号 | 例 |
|---|---|---|
| 事实 | 「不对」「不是」「错了」「应该是」 | 「不是 probe_secs，是 connect_timeout」 |
| 偏好 | 「以后」「下次」「别再」「记住」 | 「以后写周报别用表格，用条目」 |
| 风格 | 「太长了」「说人话」「直接说结论」 | 「三句话说完」 |
| 流程 | 「先…再…」「顺序反了」「漏了一步」 | 「改代码前先跑 check-boundaries」 |

**流程**（沿用 `echo.rs` 铁律：**AI 出决策 JSON，Rust 写盘，模型物理上无写权**）：

```
命中 → 本轮末尾后台起一次轻量蒸馏（不阻塞回复）
     → 模型输出 { kind, target: persona|memory|skill, statement, scope, confidence }
     → Rust 执行：
         confidence < 0.6        → 只记账不入库（等复现）
         同一 statement ≥2 次     → 升级写入
         target=persona          → 追加到 PERSONA.md「他教过我的」
         target=memory           → 新建 memory/<slug>.md + 更新 index.md
         target=skill            → 排队给 F15
     → 对话流里出现一条灰色小字：「记下了：写周报用条目不用表格」 [撤销]
```

**三条防污染**：**两次原则**（单次只记账，第二次才固化）· **60 秒可撤销**（撤销即删文件）· **可见可改**（设置页「它记住的事」列表，每条对应磁盘文件）。

**验收**：4 类各 10 条样本识别率 ≥80%、**误报率 ≤10%**（误报比漏报致命）· 说两次的偏好第三次真的生效（人工验 5 组）· 撤销后磁盘干净 · 对首 token 延迟影响 = 0。

### 5.9 F9 · 日程托管：什么形态都能丢给它

**导入**（任意形态，都走多模态理解 + 结构化）：截图（飞书/钉钉/Outlook 日历）· Excel / CSV · `.ics` · 微信群里那段"周三下午三点开会" · 你口述一句 · 手动填。

**解析后它干三件事**：

1. **提醒**：会前 15 分钟一次（可调）。**已经在会里就不打扰。**
2. **会前备料**（这条是差异点）：把上次同名会议的纪要、相关文件、上次遗留的待确认事项，**在会前 15 分钟凑成一页**推给你。
3. **接上录音**：日程里标了"要录"的，到点问一句要不要开始（**不自动开**），会后自动走 F5 流水线。

**冲突检测**：两个会撞了、会中间只有 10 分钟赶路、连开三小时没有空档吃饭 —— 都在排进去的时候提一句。

### 5.10 F12 · 失败托底

**钩子**：CI 失败 / 命令非零退出 / 定时活儿失败 / 你说了「又挂了」「搞不定」「怎么还是」。

**三段式**（写进 PERSONA.md）：

| 段 | 内容 | 要求 |
|---|---|---|
| ① 归因 | 什么挂了、**是不是你的锅** | 必须有证据（错误码/日志行/文件）。不确定就说不确定，**不准为了安慰甩锅给环境** |
| ② 先例 | 以前遇到过吗 | 必须带日期，从记忆库取。**没有就说没有，不准编** |
| ③ 两条路 | 快解 vs 根治，各自代价 + 建议 + 现在能点的一步 | 必须给出一个**现在就能点的动作** |

**工程量 1.5 人日，全 PRD 投入产出比最高的一条。**

**验收**：15 个失败场景三段式完整率 ≥13/15 · 「先例」日期与记忆库可对账，**编造率 0** · 托底后 10 分钟内用户继续推进任务的比例 ≥60%。

### 5.11 F13 · 饮食记账：只记，基本不判

**做什么**：拍一张 → 认出来 → 记一笔 → 一句人话。一周回看一次，只陈述。

**坚决不做什么**（这个功能死于多做）：
- ❌ 卡路里 / 蛋白质 / 营养评分 —— 不准，且没人真看
- ❌ 减肥计划 / 体重 / BMI —— 不是我们的事，且是医疗健康的敏感边界
- ❌ "建议您搭配蔬菜" —— 这是让人删 App 的那句话
- ❌ 打卡、连续天数、饮食评分

**唯一会主动说话的两种情况**：
1. 你自己说过想改的事（"想少点外卖"）→ 一周提一次，带数据不带评价
2. 饭点过了很久还没记录 → 一次，"还没吃吧？"

数据落 `~/Polaris/xiaoman/meals/<date>.json`，明文，**一键清空**。多模态识别失败就存图不认，**不瞎猜**。

### 5.13 F14–F18 · 其余功能（沿用 v1.1 设计，此处从简）

## 6. 它怎么说话

> **旧版这一章有 2000 字，包括三道闸、一份白名单、十条禁令和一套抽检打分。这版全删了。**
> 原因很简单：**那套东西是在教一个人怎么证明自己不是机器人，而一个人不需要证明这个。**
> 剩下这三条就够了。

**① 有具体的东西。**
「注意休息」是废话。「这是第三个凌晨了，前两天下午你都在返工」是话。
区别不在温度，在**有没有指向一个真实存在的事**。

**② 说完就过。**
顺口关心一句可以，说完不追问、不重复、不要求回应、不做成每日仪式。
一天一两句是搭子，一天十句是推销。

**③ 像人一样长短交错。**
不要每句都 20 到 30 字。该短就短。像这样。
不用「首先/其次/综上所述」。不用感叹号堆热情。不夸他。不在结尾问「还有什么可以帮您的吗」。

**就这三条，写进 `PERSONA.md`。** 不做抽检、不做打分、不做违规率看板——**那些东西不会让它更像人，只会让写它的人更累。**

真要判断做得好不好，只有一个办法：**把它说的话念出来。念着别扭就是不对。**

### 7.3 调度器下沉（P0 必做）

现状：`automation.ts` 用前端 `setInterval(60_000)`，**App 关着就不跑**，而"每天 9 点给我简报""14:15 给你备料"这类承诺必须在你打开电脑前就完成。

方案（最轻）：**复用 `echo.rs` 已有的做梦定时器线程**——它已经处理了「错过钟点开机补做」「一天只跑一次」「本地时区」这三个最麻烦的问题。把 automation flow、节律、日程提醒的 due 判定全挂进同一个 tick：

- flow 定义仍存前端，但**镜像一份到 `~/Polaris/data/flows.json`**（前端每次增删改写盘）
- 内核 tick 读 `flows.json` + `rhythm.json` + 日程，due 的通过现有 chat 管线起一轮
- 开机补做：错过的 daily flow 开机 2 分钟后补跑（每天仅一次，沿用 `run_on_boot` 语义）
- **节律提醒不补做**（错过就是错过，见 §5.3.1）

**不引入 cron 库**（`echo.rs` 已证明手写 hour 判定够用）。

## 8. 指标

### 8.1 北极星

**「有多少人给它换了形象」**（首周内完成形象工坊的用户占比）

选它的理由：**这是"它成为我的"的唯一可观测瞬间**。换过形象的用户，后面所有留存指标都会是另一条曲线。目标：**首周 ≥60%**。

第二北极星（长期）：**「它记住的有效条目数」**——memory + persona 中最近 30 天被实际命中过的条目。它同时代表"懂你的程度"和"用户没删掉 = 认可"。

**刻意不看的虚荣指标**：技能总数、记忆总数、消息数、DAU 单看。豆包的 800 万智能体就是被这类指标骗死的。

### 8.2 分层指标（3 个月目标）

| 层 | 指标 | 目标 |
|---|---|---|
| 形象 | 首周换形象率 | **≥60%** |
| 形象 | 九帧一致性盲评通过 | ≥7/9 |
| 身体 | 提醒响应率（点了「喝了/起来了」） | ≥40% |
| 身体 | **提醒被整条关掉的比例** | **≤15%**（这是最重要的反指标） |
| 身体 | 打断投诉（连续输入期间弹出的提醒数） | **0** |
| 录音 | 用过录音的用户中，一个月内录 ≥5 场的比例 | ≥50% |
| 录音 | 「顺手的产物」被打开率 | ≥70% |
| 录音 | 会后待办真的被完成的比例 | ≥40% |
| 范围 | 从「可动草稿」升到「可自主执行」的比例 | ≥30%（信任度的直接度量） |
| 干活 | 定时活儿产物 24h 内打开率 | ≥60% |
| 懂你 | USER.md 中"推断得出而非直说"的条目 | ≥8 条 |
| 懂你 | 纠正后同类任务的行为改变率 | ≥80% |
| 留存 | 案头 7 日打开率 | ≥70% |
| 反脆弱 | 定时活儿静默失败数 | **0**（必须全部可见） |

### 8.3 反指标（触发即刹车）

- **身体提醒被整条关掉 >15%** → 分寸没做对，回去改 §5.3.1，不要加功能
- 定时活儿被关闭 >30% → 简报在凑数
- 「它记住的事」被手动删除 >20% → 纠正捕获在误报
- 人格自我修订被还原 >15% → 修订闸门太松
- **录音功能开启后又永久关闭 >20%** → 隐私没做到让人放心，这是最贵的一条
- **形象生成后又换回默认 >30%** → 生成质量不达标，宁可先不上

## 9. 隐私与合规

### 9.1 数据分级与去向

| 数据 | 敏感度 | 默认去向 | 用户可控 |
|---|---|---|---|
| 代码 / 项目文件 | 中 | 本地，按范围卡授权 | 逐目录 |
| 人格 / 记忆 / 画像 | 中 | 本地明文 | 可见可改可删可导出 |
| **形象照片与生成帧** | 中 | 本地；生成时上传到**你自己配置的**生图服务商 | 可选纯本地兜底（默认款） |
| **录音音频** | **高** | 本地；转写时按你选的走本地或云端模型 | 7 天自动删 / 立即删 / 永久，一键忘掉 |
| **转写全文** | **高** | 本地明文 | 随会议一起删 |
| **饮食照片与记录** | **高** | 本地 | 一键清空 |
| **作息 / 键鼠活跃度** | **高** | 本地，**只存时间戳与活跃布尔值** | 一键清空，**不下发手机端** |

**三条铁律**：① **不上传、不用于训练**；② 任何需要出门的调用（云端模型）**必须是你自己配置的 key**，且首次明确告知；③ 每一类都有**一键删干净**，删完 `grep` 得为零。

### 9.2 录音的额外义务

录音是唯一涉及**第三方**的功能，单独立规（详见 §5.5.4）：绝不常开 · 状态三处可见且不可隐藏 · 一键告知话术 · 原始音频默认 7 天删 · 一键忘掉 · **他人语音不进长期记忆、不建声纹库**。

产品内首次使用展示一次法律提示：**录你自己参与的对话在多数场景合法，但告知在场者是基本礼貌，部分场景是法定要求；录到的内容不要外传。**

### 9.3 与《拟人化互动服务管理暂行办法》的关系

- **定位**：工作搭子 / 工作助手 / 数字同事。产品文案、UI、宣传物料**不使用**「陪伴、恋人、家人、树洞、情感支持、永远在你身边」。
- **不做**：情感陪伴、虚拟亲密关系、心理咨询、情绪日记、心情打卡、"陪我聊会儿"入口。
- **照做**：首启明确写「小满是 AI，不是真人」（第十八条标识义务，虽属豁免范围仍主动做）。
- **人格修订提示词写死**禁止增加「让用户更依赖你、更难离开你」的条款（对应第八条）。
- **未成年人**：不提供任何未成年人向功能，也不采集年龄（**不适用即不需要，避免过度收集反成风险**）。
- **数据**：全本地，提供导出与删除（第十六条精神，也是我们的卖点）。
- **伦理底线**：不做主动心理干预（超出工作搭子边界）；但若用户明确表达自伤意图，回复中给出求助渠道并停止任务型互动。

**上线前法务复核一份定位说明书**，逐条论证适用第二条不适用条款。条款引用以官方原文为准。

## 12. 明确不做的事

- ❌ **智能体市集 / 人设商城 / 形象商城 / 角色广场** —— 豆包已用 800 万个证明这是负资产。**形象值钱是因为是你捏的，不是因为好看**
- ❌ **3D / 直播级数字人** —— 成本高、拖性能，且精细度与信任度不相关
- ❌ **多个数字员工同时在线** —— 分散注意力，且每个都不够懂你。现有「专家团」已覆盖多视角，那是**能力编排**不是**人格分裂**
- ❌ **情感陪伴 / 虚拟亲密关系 / 心理咨询 / 情绪日记 / 心情打卡** —— 合规红线 + 定位红线
- ❌ **主动发起闲聊** —— 星野的死法
- ❌ **常开录音 / 后台偷录 / 声纹长期库** —— 一次事故毁所有
- ❌ **健康打卡 / 卡路里 / 体重 / 减肥计划 / 健康分 / 连续天数成就** —— 搭子一旦开始记分就变成了监工
- ❌ **医疗建议** —— 不是我们的事，边界清楚
- ❌ **真人写实数字人 / 换脸 / 用别人的脸** —— 肖像风险 + 定位红线
- ❌ **云端人格同步为默认** —— 违背核心卖点。多设备同步走用户自己的 NAS / 协作主机（Polaris 已有隧道与 fsface）
- ❌ **以情绪为钩子的召回推送**（"今天还没跟我说话呢"）—— 违反第八条与第十九条，且很烦
