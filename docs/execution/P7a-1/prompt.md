# 任务 P7a：端到端演练脚本（Codex 编写，Claude 在沙箱外实际运行）

先读 `docs/tasks/P7-drills.md`（演练清单与用户决定）。你的沙箱不能运行 Docker、不能联网、不能派生 Node 子进程；本任务**只编写脚本与文档**，由主控在真实环境运行。脚本要写到"主控一条命令即可跑、输出机器可读结果"的程度。

## 产出（`drills/`）
1. `drills/README.md`：每个演练的前置条件、命令、预期结果、清理方式。
2. `drills/lib/`：通用工具（启动/停止进程、等待就绪信号而非固定 sleep、收集日志、生成结果 JSON：`{drill, step, status: pass|fail|blocked, evidence, durationMs}`）。
3. 演练脚本（bash 或 Node/TS 均可，与仓库现有风格一致；Node 脚本用 agentd 已有依赖，不新增依赖）：
   - **D1 Agent 主链路**：构建 agentd 生产包与服务端壳，以 Pi 后端启动；通过服务端 HTTP/IPC 发起：普通对话、带工具的编码任务（临时目录内建文件、运行、修改）、图片附件、长对话触发压缩（可用较小上下文窗口配置加速）、中途 abort、steer/followUp、切换模型后空闲会话重开保留历史；记录首字延迟、单轮耗时、取消到 done 时间、agentd 内存。凭据：从环境变量 `DRILL_PI_AGENT_DIR` 指向的目录**复制**到临时目录使用，结束删除；脚本中绝不打印凭据内容。
   - **D2 故障恢复**：运行中 `kill -9` agentd → 断言 error→done、自动重启、会话按 id 恢复；连续崩溃 → 熔断状态；凭据锁双进程强杀回收（复用已有测试思路，但用真实进程）。
   - **D3 权限与沙箱**：四档权限实操（manual 档通过 API 回应允许/拒绝/超时）；符号链接 + `..` 越权被拒；真实 Docker 沙箱：按 P3b 策略创建容器，`docker inspect` 断言挂载（仅项目可写 + 只读 KB）、`CapDrop` 含 ALL、`no-new-privileges`；容器内 `ls` 看不到 `~/Polaris/data`、`*.key`；失败命令非零退出码；停掉 Docker 后沙箱调用报错不回落宿主；项目本身是指向受保护目录的符号链接时被拒。
   - **D4 互联（本机多容器）**：基于 `deploy/singapore/` 的配置，用本地构建的镜像（`Dockerfile` 服务端壳、`Dockerfile.relay`）起权威 + relay + 两个成员主机 + 一个"新设备"；本地自签 CA（生成到临时目录，演练后删除）；断言：账号密码登录即成网；relay 下发生效；新设备立即可读写、旧设备收到通知、一键吊销后新设备在一个拉取周期内失去访问；窗口期高风险操作需旧设备批准、自批被拒；权威不可达时高风险被拒、已有会话可用；篡改/回滚吊销清单被拒；邮箱验证码接口对已注册/未注册邮箱响应一致（R11）；频控 429；备份→恢复→指纹校验（真实 age）。
   - **D6 回归总表**：全部测试套件连续 N 次（参数，默认 5），汇总通过率；三种构建警告数；行数检查。
4. 每个脚本支持 `--only <step>` 与 `--keep`（失败时保留现场供排查）。

## 规则
- 只改 `drills/`、必要的 `.gitignore`、`docs/`。不改产品代码；若发现产品缺少演练所需的接口/开关（例如注入故障、缩小上下文窗口），在结果中列出，由主控决定。
- 演练不得访问真实的用户数据目录（`~/Polaris`、`C:\Users\mi\...`）；全部用临时目录，结束清理。
- 不新增依赖；脚本 `set -euo pipefail`（bash）；每文件 ≤500 行、每行 ≤500 字符。
- 你能做的静态检查：`bash -n`、`npx tsc --noEmit`（如为 TS）、脚本自身的单元测试（用假命令替身）。不 commit。
