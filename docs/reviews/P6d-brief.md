# 审查 brief：P6d 浏览器端登录编排 HTTP 入口 + 审批设备名称
附 `P6d.patch`（含测试）。背景：P6b 只有本机 Tauri 登录编排；P6d 为 Web 版（服务端壳）提供等价 HTTP 入口。设计约束见 `docs/tasks/P6d-web-login-and-names.md`。
## 验收条件
HTTP 入口复用同一编排函数与状态模型（`interconnect:{stage,state,error,retryable}`、`relayConfig`），提供状态查询与重试；沿用登录频控与可配置频控；不把本机 LocalConsole 准入暴露给远程；浏览器会话的设备身份不能成为绕过"新设备窗口期高风险审批"的通道；失败信息不泄露账号是否存在；审批数据附带发起设备名称/平台（只读来自 mesh 目录），未知/已吊销显示占位；未改 `mobile/`。
## Claude 实测
三种构建 0 警告；collab 154 两次全过；内核 225 通过；vitest 84/84；vite build 通过。
## 已知（不必复述）
邮箱验证码接口存在既有账号枚举问题（重构前即有），已另派 R11 修复。
## 请重点审查
浏览器会话设备如何生成与过期、能否被批量生成以刷新"新设备"状态或绕过频控；会话设备在窗口期内是否确实受高风险审批约束；HTTP 编排的重试是否幂等（重复登记设备、重复建隧道）；状态查询是否只能看到自己的编排；CSRF（Cookie 会话时）与 CORS 配置；设备名称字段是否做了输出转义（前端 XSS）。
